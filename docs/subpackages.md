# 小程序分包与体积检查

## 当前划分

- 主包保留首页、消息、集市、购物车、搜索、个人中心及下单、订单、售后等常用消费页面。
- 商品管理、库存、采购、拣货、发货、管理端售后、统计明细和直播页面按现有目录声明普通分包。
- `pages/logistics` 的打印员和快递批量管理页面共用一个分包。
- 销售页 `pages/adminSales` 继续留在主包，因为主包组件 `components/managerSales` 直接引用它的 WXML 和 WXSS；将其单独分包会造成主包跨包引用。
- 现有 58 个页面的路径全部保留，导航、分享、客服卡片和历史入口继续使用原地址。公共组件、工具、模板和构建后的 npm 依赖保留在主包，普通分包可以直接引用。

分包根目录无需搬到 `packages/` 下；微信会按 `app.json` 的 `subPackages[].root` 划分。新增页面时，管理类功能优先进入对应分包，避免继续往主包堆积。

## 打包排除

`project.config.json` 的 `packOptions.ignore` 排除了测试目录、`node_modules` 原始依赖、`.map` 源码映射及包管理清单。运行时使用的 `miniprogram_npm` 中的 JavaScript 仍正常打包。

## 本地检查

在 `xzm-today/miniprogram` 下执行：

```powershell
npm run check:packages
npm test
```

体积检查会列出每个包的源码体积、主包余量和主包最大的文件，并检查页面缺失、页面重复、根目录嵌套及 tabBar 页面归属。任一包的源码体积超过 2 MiB 时，命令返回失败；主包超过 1.5 MiB 建议预算时输出提示。

`tests/unit/packageLayout.test.js` 还会检查 JS 依赖、组件声明、WXML 模板及 WXSS 导入，防止主包引用分包文件或分包之间同步引用，并把主包 1.5 MiB 预算作为回归检查。

这些数据是按源码文件统计的，不是微信编译产物的精确大小。微信会进一步编译、压缩和生成代码，最终应在微信开发者工具的代码依赖分析/包体积信息中复核，并重新打包确认。不要通过开启大包支持掩盖实际超限。

本次调整后的源码参考值：主包约 1.44 MiB，最大分包约 168 KiB；20 个主包页面、37 个分包，合计 58 个页面。源码统计会随业务改动变化，以命令输出为准。
