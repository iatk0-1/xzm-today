# 小程序角色切换

“我”页显示当前角色，点击“切换角色”从服务端实际授予的角色中选择。每个登录账户都有普通用户角色；存在有效档口分配时可选档口负责人；管理员账户可选管理员。管理员只有同时拥有有效档口分配时才能选择档口负责人。

## 请求与权限

- `GET /api/v1/auth/roles` 返回可选角色字符串数组，例如 `["user", "stall_manager", "admin"]`。使用登录凭证校验账户身份，不受当前浏览角色限制。
- 普通业务请求和图片上传带 `X-Active-Role`，取值为 `user`、`stall_manager` 或 `admin`。后端校验角色资格，然后按当前角色执行原有接口权限判断。
- 未携带角色头的旧客户端继续使用原有默认身份。
- 登录凭证保留账户身份；本地 `selectedRole` 保存所选身份，`role` 用于页面现有权限判断，刷新凭证不会覆盖所选身份。
- 切换成功后重新打开“我”页，清除旧页面栈和列表分页；再次进入首页或市集会按所选身份重新加载。
- 可选角色刷新时发现所选身份已被撤销，会恢复普通用户身份。后端始终独立校验，修改本地存储不能获得额外权限。

## 首页与市集数据

| 当前角色 | 首页商品 | 市集心愿 |
| --- | --- | --- |
| 普通用户 | 全部正常可展示商品 | 全部正常可展示心愿 |
| 档口负责人 | `product.seller_id` 为当前账户的商品 | `wish.created_by` 为当前账户的心愿 |
| 管理员 | 全部正常可展示商品 | 全部正常可展示心愿 |

数据筛选在后端分页前完成，列表与总数使用相同条件。原有上架、删除、内容审核等展示规则继续生效。商品管理请求 `manage=true` 继续按创建归属和有效档口分配共同限制可管理商品。

## 部署与验收

先部署后端，再发布小程序，无须新增数据库结构。历史迁移 V52 曾将缺少归属的商品 `seller_id` 填为账户 1；这类记录无法自动还原真正创建人，会按现有归属展示。历史归属如有偏差，需核实后再单独处理。

验收时使用同时具备管理员及档口分配的账户，依次切换三个角色，检查菜单、首页商品、市集心愿及分页。切为普通用户时管理员接口应返回 403，切回管理员后恢复管理员功能。单独具备档口分配的账户只应看到普通用户和档口负责人两个选项。
