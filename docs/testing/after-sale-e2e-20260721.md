## 已确认缺陷

### AFS-001：用户撤销售后后无法重新申请（已修复）

- 严重级别：P1
- 售后 ID：`337777930237120512`
- 前置状态：售后 `pending`
- 操作：用户撤销售后，再对相同订单项重新申请。
- 预期：撤销释放订单项，允许重新申请。
- 实际：重新申请返回 HTTP 400，提示该商品已有进行中的售后。
- 原因定位：`AfterSaleService.apply()` 的防重复逻辑只放行 `rejected`、`refunded`，未放行 `cancelled`。

### AFS-002：仓库验收失败后仍可退款（已修复）

- 严重级别：P1（资金风险）
- 售后 ID：`337778792955121664`
- 操作链：退货退款审核通过 → 用户寄回 → 管理端选择“验收不通过” → 管理端退款。
- 预期：验收失败时退款接口必须拒绝，售后保留待人工处理状态。
- 实际：退款成功；售后与明细均变为 `refunded`，订单变为 `cancelled`。
- 日志证据：`receive_fail` 后紧接 `refund`。
- 原因定位：新版明细退款分支仅检查明细状态 `received`，未检查主单 `warehouse_check=pass`。

### AFS-003：混合售后收货后主单错误保持 approved（已修复）

- 严重级别：P1
- 售后 ID：`337785020481540096`
- 订单 ID：`337776022122401792`
- 场景：部分发货订单同时包含：
  - 未发 1 件：`refund`，已自动退款；
  - 已发 1 件：`return_refund`，仓库验收通过。
- 预期：退货明细收货后，主单应进入可继续退款的明确状态（如 `received`），管理端显示“确认退款”。
- 实际：
  - `refund` 明细：`refunded`
  - `return_refund` 明细：`received`
  - 主单：仍为 `approved`
- 影响：管理端按 `approved` 继续渲染“仓库收货”，无法正常展示“确认退款”；重复收货还可能重复执行库存入库。
- 原因定位：`updateMainStatus()` 未覆盖 `refunded + received` 的混合状态组合，落入默认 `approved`。

### AFS-004：混合售后第一次部分退款写入主单级退款 ID，阻断剩余明细退款（已修复）

- 严重级别：P1（资金与状态一致性风险）
- 售后 ID：`337785020481540096`
- 操作链：审核混合售后时，未发货 `refund` 明细先自动退款。
- 实际：主单立即写入 `wechat_refund_id=e2e_after_sale_337785020481540096`；之后已发货 `return_refund` 明细收货完成，再调用退款接口时命中主单级幂等判断并提前返回。
- 最终状态：
  - 主单：`approved`
  - 退货明细：`received`
  - 仅退款明细：`refunded`
  - 订单：`shipped`
- 预期：幂等与退款交易应按可退款批次/明细管理，第二阶段退款可以继续执行，最终主单与全部明细进入 `refunded`。
- 原因定位：`AfterSaleService.refund()` 在入口按主单 `wechatRefundId` 全局幂等，无法支持混合售后的分阶段退款。

### AFS-005：微信退款 `PROCESSING` 被误判为失败（已修复并完成 dev 回归）

- 严重级别：P1（真实资金状态与本地状态短暂不一致）
- 两笔真实退款首次均收到微信正常中间态 `PROCESSING`，后端将退款交易标记为 `failed`，错误为 `Wechat refund status=PROCESSING`。
- 使用相同商户退款单号再次提交后，两笔退款均成功，重试次数均为 2。
- 原因定位：`AfterSaleService.attemptRefund()` 仅接受 `SUCCESS`，将微信异步处理中状态直接抛异常并落库为失败。
- 预期：`PROCESSING` 应保留处理中状态，并通过微信回调或主动查询确认终态，不能按失败处理。

### AFS-006：未发货仅退款成功后库存未回补（已修复并完成 dev 回归）

- 严重级别：P1（库存账实不一致）
- 订单 `338521373913649152` 退款后库存流水只有 `reserve`、`sale`，缺少 `refund_in`；SKU 库存仍为 0。
- 为继续执行后续真实支付场景，已通过正式商品更新接口把测试 SKU 恢复为应有的 1 件。
- 原因定位：退货退款在仓库验收通过时调用 `stockService.refundIn()`；仅退款成功路径 `markRefundSuccess()` 只更新退款和订单状态，没有执行对应库存回补。
- 预期：仅退款成功后按实际退款明细幂等执行 `refund_in`，重复退款回调或重试不得重复入库。

### AFS-007：仅退款失败时管理端缺少“重试退款”入口（已修复并完成 dev 回归）

- 严重级别：P2
- 当售后类型为 `refund`、状态为 `approved` 且自动退款失败时，管理端详情只显示“仓库收货”，没有“确认退款/重试退款”按钮。
- “仓库收货”不适用于未发货仅退款，导致管理员无法从页面恢复失败退款。
- 预期：仅退款失败时显示明确失败原因和“重试退款”操作；退货退款才显示仓库收货。

### E2E-001：待付款取消脚本选择了错误按钮（已修复并完成 dev 回归）
